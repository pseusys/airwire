# Image texture synthesis: irregular scatter layout (Wu & Wang, full technique)

> **Status:** implemented and kept, for the scattered-anchor mechanism (§4 point on anchor mask
> and traversal).
> Measured results confirmed it removes the row-banding look for
> `value_noise`/`voronoi`/`reaction_diffusion`; `attractor` untouched, as planned.
> The overlapping-candidate half of the technique (§4's `PatchLibrary` `stride` point) was
> measured across `stride` in `{1, 2, 4, 8}` and **not adopted as the default** -- no consistent
> quality winner across flavors, and small strides cost up to ~90x more wall-clock time.
> `stride`
> stays as a real, working `PatchLibrary` parameter, just not the shipped default.

## 1. Problem

The position-guided redesign (same day, earlier) fixed a real alignment bug and measurably
improved large-scale-structure survival for `voronoi`/`reaction_diffusion`, but left the seed/gap
**row alternation** itself untouched.
Generated example images (upscaled PNGs, `value_noise` and
`voronoi`) showed this clearly: exact, smooth seed rows alternate with visibly "quilted" gap rows,
reading as horizontal banding -- because a gap row's content is quantized to whichever patch from a
small, non-overlapping tile palette scores best, and a smoothly-varying gradient or a large flat
cell rarely has an exact match sitting in that palette.

## 2. What Wu & Wang's technique actually does

Researched directly (the algorithm isn't just "scatter instead of rows" under one name) -- it
bundles two separable ideas:

1. **Scattered anchor placement.** Known-content "source patches" sit at scattered 2-D positions
   across the whole canvas, not confined to whole rows.
2. **Overlapping candidate patches.** Gap-fill candidates are drawn from overlapping, pixel-shifted
   crops of the source texture, not a coarse non-overlapping tile grid -- this is what actually
   reduces the "quilted" quantization, separately from where anchors sit.

Their index-table/source-texture-recovery bookkeeping doesn't apply here (confirmed against the
module's own docstring): that exists because *their* source texture is secret content to
reconstruct, and ours is a public, regenerable codebook already agreed by both ends via the shared
seed.
The user chose to implement both (1) and (2) together, and a blue-noise/Poisson-disk-style
scatter (genuinely irregular) over a deterministic checkerboard/lattice for the anchor pattern.

## 3. Hard constraints (unchanged)

Same as the position-guided redesign: exact bit-for-bit invertibility; every encoding step stays a
`(candidate, weight)` list fed to the existing, unmodified arithmetic coder
(`core/sources/arithmetic.py`); decode identifies "which patch was placed" by exact byte match
against a candidate library.

## 4. Design

**Scope.** Applies only to the three position-guided flavors (`value_noise`, `voronoi`,
`reaction_diffusion`).
`attractor` keeps its existing row-alternating, local-edge-only mechanism
completely untouched (own code path, not a shared, branch-heavy one) -- it has no positional
structure to place 2-D anchors by, same reasoning as the position-guided redesign's fallback.

**Anchor mask.** A `(period, period)` boolean grid (`period` = the texture's own patch-grid period,
e.g. 16), computed once from the same seed already used for the texture -- no secret data --
and wrapped modulo that period for a canvas of any height, exactly like the texture itself already
tiles.
Generated by deterministic dart-throwing (a Poisson-disk approximation; the domain is tiny,
so no spatial-acceleration structure is needed): shuffle every grid cell with a seeded RNG, accept
a cell as an anchor if it's at least a chosen minimum grid-distance from every already-accepted
anchor, until no more qualify.
The minimum distance is tuned empirically to land near a target anchor
density (roughly the ~50% capacity trade-off the row-alternating design already has), and the
actual achieved density is what gets measured and recorded, not assumed.

**Traversal.** A plain row-major raster scan of the whole canvas, one cell at a time -- no more row
pairs.
A gap cell's only possibly-known neighbors are **above** (previous row, same column) and
**left** (same row, previous column); both are always already resolved in this scan order, so
"below" and "right" are never referenced (a genuine simplification versus needing an
always-guaranteed seed row on both sides, as the row-alternating design does).
Row 0 no longer
needs to be a mandatory full anchor row either -- it follows the mask like any other row, with no
"above" term available for its gap cells (same missing-neighbor pattern column 0 already has for
"left").
The walk stops once the row in progress completes *after* the payload is exhausted -- no
trailing bonus row needed, since nothing depends on a "below" neighbor anymore.

**Overlapping candidate library.** `PatchLibrary` gains a `stride` parameter: `stride=patch_size`
(today's behavior, used unchanged to render anchor content via `_guide_patch`) versus a smaller
`stride` for the gap-fill candidate pool -- every unique `patch_size`-square window starting at any
pixel offset that's a multiple of `stride`, wrapped periodically per axis (an overlapping crop can
straddle the texture's wrap boundary mid-patch, unlike today's always-tile-aligned crops, so this
needs a proper per-row/column modulo extraction, not a simple contiguous slice).

**Performance.** `stride=1` on a 128x128 texture yields up to 16,384 raw candidates before dedup,
versus today's ~256.
`_candidate_weights`' per-candidate cost must be vectorized (one NumPy call
over a stacked `(N, patch_size, patch_size, 3)` array, not a Python loop over `library.patches`) to
keep this practical.
`stride` itself is a tunable constant, chosen empirically (quality *and*
wall-clock time measured together), not assumed to be `1` just because that's the literal reading
of "every possible offset."

## 5. What does not change

The arithmetic coder, the wire format, `attractor`'s mechanism, the four texture flavor
identifiers, the periodicity fixes from the position-guided redesign.

## 6. Measurement and rollback plan

Same methodology as both prior experiments this session:

- Anchor-mask determinism and density (lands in a sane band, not clumped or empty) as new unit
  tests.
- Full round-trip correctness per flavor, including at least one payload long enough to
  exercise mask tiling past one period.
- A wall-clock benchmark at the candidate `stride` being considered, to confirm the vectorized cost
  computation keeps this practical before picking a final value.
- Seam MSE, the "guide fidelity" metric, and direct visual comparison (upscaled PNG, before/after),
  same as the position-guided redesign, specifically checking whether the row-banding look is
  actually gone.
- If a flavor's results are worse, or round-trip correctness breaks and can't be fixed quickly,
  that flavor reverts to the position-guided (row-based) mechanism it has today, and the outcome
  gets recorded in `memory/rejected-ideas.md`.

Python (`core/sources/synthesis.py`, `core/tests/test_synthesis.py`) first; `web-demo/` port is a
follow-up once these results are confirmed, not part of this same pass -- this change has more open
empirical parameters (anchor density, candidate stride) than the position-guided redesign did, so
validating them once before porting is worth the sequencing cost.
